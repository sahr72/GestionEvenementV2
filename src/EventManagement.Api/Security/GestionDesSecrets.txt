Initialiser les secrets (une seule fois par projet): dotnet user-secrets init --project src/EventManagement.Api
Définir la clé de signature: dotnet user-secrets set "Jwt:SigningKey" "votre-cle-super-secrete-de-32-char!" --project src/EventManagement.Api
Contrainte : pour HMAC-SHA256, la clé doit faire au moins 32 caractères (256 bits). Une phrase comme celle ci-dessus suffit amplement pour un labo.
Vérifier que votre Program.cs lit bien cette section: 
builder.Services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
    .AddJwtBearer(options =>
    {
        var jwtSection = builder.Configuration.GetSection("Jwt");

        options.TokenValidationParameters = new TokenValidationParameters
        {
            ValidateIssuer = true,
            ValidateAudience = true,
            ValidateLifetime = true,
            ValidateIssuerSigningKey = true,
            ValidIssuer = jwtSection["Issuer"],
            ValidAudience = jwtSection["Audience"],
            IssuerSigningKey = new SymmetricSecurityKey(
                Encoding.UTF8.GetBytes(jwtSection["SigningKey"]!))
        };
    });
    Point critique : si SigningKey est null ou vide, Encoding.UTF8.GetBytes lèvera une exception au démarrage ou la validation échouera systématiquement. 
    Le labo ne fonctionnera pas sans cette clé renseignée.

Issuer / Audience : vous pouvez laisser EventManagementLab, ce n’est pas sensible. L’important est que 
l’émetteur de token (votre code d’émission) utilise les mêmes valeurs.
SigningKey : obligatoire. Sans elle, aucun jeton ne peut être signé ou validé. Utilisez dotnet user-secrets comme indiqué ci-dessus.

Si dotnet user-secrets init renvoie une erreur disant que l’ID est déjà présent, c’est normal : le UserSecretsId existe déjà dans le .csproj. 
Vous pouvez passer directement à l’étape set.

dotnet user-secrets init --project src/EventManagement.Api
Set UserSecretsId to 'ba40c1d9-2fa7-4ee6-a36e-c16ff433c534' for MSBuild project 'C:\Projects\GestionEvenementV2\GestionEvenementV2\src/EventManagement.Api\EventManagement.Api.csproj'.
Cet Id est un C'est un GUID que le SDK .NET a écrit automatiquement dans votre .csproj :
<PropertyGroup>
  <UserSecretsId>ba40c1d9-2fa7-4ee6-a36e-c16ff433c534</UserSecretsId>
</PropertyGroup>
Il sert uniquement de clé de liaison entre votre projet et le fichier secrets.json stocké localement sur votre machine. 
Le SDK s'en sert pour retrouver vos secrets quand l'application démarre.
Donc, dotnet user-secrets init --project src/EventManagement.Api Le SDK a :
1.généré ce GUID ;
2.l'écrit dans EventManagement.Api.csproj ;
3.préparé un fichier secrets.json vide lié à ce GUID.
